# Exchange-wallet flow investigation and validation

## Outcome

No BTC/ETH exchange-wallet provider has been approved as a required safety input. Both assets retain `exchange flows` in the missing-input list and both trading horizons remain NO TRADE, including when all other inputs are available and the manual macro check is clear. This change adds a real public Coin Metrics availability request and defensive diagnostic parser, not a verified real-time exchange-flow feed.

The adapter requests `FlowInKRKNtv` and `FlowOutKRKNtv` together for the same asset, provider, exchange and daily interval. It never substitutes trade volume, CVD, price changes, ETF flows, exchange reserves or net-flow-only data. Even a returned payload claiming `verified=true` cannot unlock ENTER. There is deliberately no approved exchange-flow provider in the safety gate yet.

## Timestamp and completeness rules

The diagnostic parser requires explicit timezone-aware timestamps, UTC daily alignment, correct asset identity, both nonnegative finite native amounts, unique contiguous daily observations, nonempty data and no unfinished pagination. Missing/null amounts are not zero. Transport, HTTP, quota, JSON and timestamp failures return unavailable with a reason. Observation timestamp and local receipt timestamp are separate; a fresh download cannot refresh an old observation. Timestamp freshness alone cannot approve a daily aggregate or establish completed coverage. The two-row bounded request has no pagination follow-up and never follows provider-supplied URLs.

Provider-labelled aggregates are displayed only as unverified diagnostics. A future approved integration must independently establish wallet attribution provenance/version, the required exchange set, transfer semantics, native asset units, matching inflow/outflow windows, completed/indexed coverage, chain finality/reorg handling, observation-window end and ingestion lag. BTC change outputs and internal wallet moves must be excluded according to an audited policy; ETH internal native transfers require trace coverage. Wrapped tokens, ERC-20 flows and cross-chain bridges cannot silently replace native BTC/ETH flows. Coin Metrics documents exclusions for BTC change and same-exchange transfers; those definitions do not certify this account's live coverage. Daily/hourly aggregates do not substantiate a current 180-second observation window.

## Live validation

The read-only check `scripts/check_exchange_flow_apis.py` attempted actual HTTPS GETs for BTC and ETH against `community-api.coinmetrics.io/v4/timeseries/asset-metrics`. Both were stopped by the environment proxy with **CONNECT 403 Forbidden before provider HTTP response**. This is an environment access limitation, not evidence of a provider 403 or missing metric entitlement. The check correctly exits nonzero because responses were not live-validated. No network restriction was bypassed. See the committed sanitized availability report alongside this document.

Regression coverage includes genuine explicit zero versus missing values, stale observations despite fresh receipt, valid/future/malformed/timezone-free timestamps, wrong assets, missing directions, negative/nonfinite/bool amounts, duplicate/gapped data, unfinished pagination, transport failure, and forged verification flags. No flow values are fabricated. The default dashboard remains read-only, with no API credentials, execution code, background collector or deployment change.

## Next work

Enable network access to the chosen documented provider through the environment's supported configuration, then check its authenticated/free metric catalog and actual BTC/ETH responses. A paid subscription should be considered only after proving granular coverage and latency can satisfy the existing rules. Until a real feed and attribution/completeness checks pass, keep NO TRADE. Independent provider fallback remains missing; falling back to estimates, coarse snapshots or a different wallet universe would not be safe.
