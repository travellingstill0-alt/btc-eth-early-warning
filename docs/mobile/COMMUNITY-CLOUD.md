## Prepared deployment entry point

Use **mobile/cloud_app.py**, not mobile_app.py or app.py. The cloud wrapper requires
a hosting secret `dashboard_access_password` of at least 20 characters before
any feed or research content is loaded. Choose a unique password generated by your
password manager. This is an extra gate, not a replacement for private viewer
access; it has no account recovery or production identity-management system.
Do not share the password in chat or commit it. Missing secrets, wrong passwords
and a disabled NO_TRADE_HOLD all fail closed. The wrapper only renders the existing
mobile UI and synthetic notification preview; no execution/push transport exists.

Dependencies for the cloud entry point are pinned in mobile/requirements.txt,
without modifying shared/root requirements. Select Python 3.12, the tested version.
Root .streamlit/config.toml enables CORS/XSRF protection, disables static-file
serving, and hides detailed errors. Secrets files and common credentials are ignored
by Git. Existing private repository status was checked through GitHub metadata;
no tracked SQLite or credential files and no standard private-key/GitHub-token/AWS
key patterns were found. This limited scan is not proof that every possible secret
in all repository history is absent. Public adapters require no exchange API keys.

Tests: missing secret and incorrect password block feeds; valid password renders
NO TRADE; locking returns to login. Full regression suite and recorded preparation
results are in `CLOUD-TEST-SUMMARY.md`. Existing research manifests remain untouched.

## Exact Android-only procedure — execute only after deployment approval

No computer or terminal is needed for these steps. Use Android Chrome; if a control
is hidden, use Chrome menu → Desktop site.

1. Review and approve the proposed free **private** deployment of this prepared
   branch, including publishing only these reviewed changes to the existing private
   GitHub repository. Do not press Deploy before approval. The remote branch currently
   lacks this locally prepared cloud wrapper; it must be pushed after approval.
2. In Chrome, sign in to your GitHub account with repository administrator access.
   Keep `travellingstill0-alt/btc-eth-early-warning` private. Do not publish its source
   or artifacts. Confirm you have not already used the one-private-app allowance.
3. Open https://share.streamlit.io . Sign in/create your Community Cloud account.
   Connect GitHub and review requested OAuth permissions yourself. Private repos
   require the documented `repo` scope and creation of a read-only deploy key.
   Do not provide account passwords, login codes or tokens to Codex.
4. Choose **Create app**, then the option to deploy from an existing GitHub repository.
   Select repository `travellingstill0-alt/btc-eth-early-warning`, branch
   `mobile/android-dashboard`, main file path **mobile/cloud_app.py**.
   Choose an available app subdomain; availability is checked by the provider.
5. Open **Advanced settings**, select **Python 3.12**, and enter this TOML in Secrets,
   replacing the placeholder on your phone with your password-manager-generated value:

   ```toml
   dashboard_access_password = "REPLACE_WITH_A_UNIQUE_RANDOM_PASSWORD_OF_AT_LEAST_20_CHARACTERS"
   ```

   Never use this literal example or paste real secrets into GitHub files.
6. After explicit deployment approval, press **Deploy**. This is the first action
   that creates the hosted service. GitHub connection/permissions also require your
   account consent. No merge is required; deploy the mobile branch directly.
7. In app **Settings → Sharing**, verify **Only specific people can view this app**.
   Keep yourself as the only viewer initially. Private repo deployments default to
   private, but check the setting before sharing the URL. Do not click Make public.
8. Open the exact HTTPS URL displayed by Community Cloud in Android Chrome.
   Sign in using your permitted identity, enter the dashboard password, and verify
   NO TRADE LOCKED, trading/live signals/notifications OFF. If asleep, use its wake
   control and wait for startup. Add to Home screen if desired; this is a shortcut,
   not an offline app or enabled Android push.
9. Check BTC and ETH timestamps, compare each displayed value against its own
   source/contract/time, confirm missing macros/flows are flagged, and verify no
   false all-clear. No hosted availability/freshness guarantee exists before this
   post-deployment check. Do not treat hosted temporary observations as archived
   research history. Continuous collection/storage remains a separate proposal.

No exact dashboard URL exists yet; it is assigned only after the approved deployment.
