# Global macro calendar and session validation

## Current outcome

The dashboard now automatically requests official calendar sources, evaluates calendar safety on every signal decision, converts parsed event/risk intervals to America/Bogota, and displays regional session windows/overlaps. **This is not yet a complete, verified live global event feed.** All 16 live source requests in this environment were denied by the outbound proxy before reaching their publishers. No production calendar adapter is safety-approved. ENTER remains blocked, even if a user checks the manual-review box or a payload claims complete/verified coverage.

Structured-event intake requires explicit `schema.org/Event` identity/title, timezone-aware start/end and scheduled/cancelled status. It is conditional intake, **not a claim that every listed site publishes that format**. A page without the supported schema is unavailable. Page-specific adapters above remain required. No generic scraper invents dates, timestamps, status, forecast or economic values from prose.

## Safety and risk rules

Defaults: 60 minutes before and 60 minutes after an event; calendar verification age 900 seconds; displayed lookahead 24 hours. UI bounds: windows 1–1440 minutes, calendar age 300–3600 seconds and horizon 1–168 hours. Backend validation rejects invalid, negative or boolean rules. Sources refresh through the active dashboard cache every five minutes; evaluation runs every minute and again at signal decision time. A refresh has a bounded request budget, no automatic retries, no redirect following and no background scheduler.

HIGH/EXTREME windows always block ENTER, even for verified schedules. An uncertain time spans the whole source-local date plus configured padding. Those endpoints represent a conservative **risk interval**, not a claimed announcement time. Scheduled events are not labelled released just because time elapsed. Explicit cancellations are handled without inventing an actual release. Missing/stale sources, incomplete category coverage, unknown schedules and malformed timestamps fail closed. Old source checks cannot be refreshed by merely updating a payload's overall retrieval timestamp. Raw source bodies are reparsed; cached normalized event/verification flags cannot bypass checks. No production adapter is approved until live schemas, timing/status, authoritative update semantics and complete interval coverage are established.

The decision includes `reason_code`: `MISSING_DATA`, `HIGH_RISK`, `HIGH_RISK_AND_MISSING_DATA`, or `MANUAL_REVIEW_REQUIRED`. Market HIGH/EXTREME and missing market inputs participate in the same distinction. Manual review remains additional protection and cannot clear a calendar blocker.

Importance is a conservative dashboard policy, not an official publisher rating: USA CPI/NFP/FOMC and ECB/BOE/BOJ/PBoC decisions are EXTREME; other required inflation/GDP/employment/PMI/speeches generally HIGH; German inflation/GDP/employment/industrial-production titles HIGH and other generic German release entries MODERATE; other informational entries LOW. All critical missing categories block independently of this rating. Importance is not downgraded using unverified expected values.

Previous/forecast/actual columns exist but remain unavailable: no verified numeric-results or consensus-forecast adapter was integrated. Provider fields claiming `verified=true` do not promote numbers. Government forecasts/projections must not be silently presented as a market consensus forecast. Revisions, reference period, units, seasonal adjustment, initial versus final releases and figure observation timestamps still need implementation before values can be supplied safely.

## Sessions and timezone handling

The module monitors **indicative regional liquidity sessions**, not official exchange opening status: Tokyo 09:00–18:00, London 08:00–17:00 and New York 08:00–17:00, in their local IANA timezones on local weekdays. It shows Colombia open/close times, active scheduled windows and pairwise overlaps. US/European DST transitions change Colombia times and overlap duration independently. These are transparent conventions: exchange-specific hours, lunch breaks, holidays, exceptional closures and Sydney/other Asian-market windows are not implemented. Holiday status is UNVERIFIED and session activity never makes a macro calendar safe. BTC/ETH remain 24/7 markets.

## Live checks and costs

`scripts/check_macro_sources.py` attempted all 16 configured URLs through the environment's supported HTTPS proxy. Every attempt received **CONNECT 403 Forbidden before a publisher HTTP response**. This is network-policy denial, not a publisher outage, schema rejection or API-entitlement response. The dedicated checker correctly exits 1; it must not be reported as a successful live provider validation. The sanitized [live report](macro-live-validation.json) records those failures. Official pages were reviewed through the research/browser connector, which does not establish successful runtime feed access.

All sources selected are public pages/calendar feeds and require no configured paid API subscription or key for these attempted requests; **cost incurred: $0**. Public viewing does not establish unrestricted bulk redistribution or access to proprietary PMI datasets. No numeric-price quote for a comprehensive commercial calendar/consensus feed was verified, and none was purchased. A paid feed would still need contractual coverage, timestamps, latency and status validation before satisfying the gate.

Next: configure supported outbound access to the selected publishers, validate actual feed bodies, complete the page/API-specific adapters and coverage proofs, and then investigate a separately licensed consensus/results source if figures are required. Until that succeeds, keep NO TRADE. No merge, deployment, automated trading, subscriptions, outbound notifications or background collection was enabled.

Validation result: **91 tests passed**, including Streamlit rendering, manual-override prevention, source/timestamp/completeness errors, DST folds/gaps, window boundaries, reason-code distinctions, forged fields and US/European DST overlap differences. The full integrated live checker passed all eight BTC/ETH primary/fallback modes; all sixteen panels returned NO TRADE with MISSING_DATA. The macro-specific live checker correctly reported failure for all sixteen proxy-blocked source requests. Compilation and `git diff --check` passed.
